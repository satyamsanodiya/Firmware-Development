# Understanding Input Buffering (stdin)

Input buffering is the process by which the C Runtime Library temporarily stores user-entered data before the application reads it.

When the user types data using the keyboard, the characters are **not directly transferred** to the application variables. Instead, they are first stored inside the **stdin input buffer** managed by the C Runtime Library.

Only when an input function such as `scanf()` or `getchar()` is executed does the runtime library retrieve characters from this buffer.

---

# Input Buffer Architecture

```

```
                Keyboard

                     │

                     ▼

        +------------------------+
        |      stdin Buffer      |
        +------------------------+

                     │

                     ▼

           scanf() / getchar()

                     │

                     ▼

             Application Variables
```

---

# How scanf() Works Internally

Consider the following program.

```c
float num1,num2,num3;

printf("\nEnter 3 numbers : ");
fflush(stdout);

scanf("%f %f %f",&num1,&num2,&num3);

float average = (num1+num2+num3)/3;

printf("\nAverage = %f",average);
```

When the user enters

```
10 20 30
```

the keyboard generates

```
'1'
'0'
' '
'2'
'0'
' '
'3'
'0'
'\n'
```

These characters are first stored inside the input buffer.

```
stdin Buffer

+--------------------------------------------------+
| 1 | 0 |   | 2 | 0 |   | 3 | 0 | '\n' |
+--------------------------------------------------+
```

When `scanf()` executes,

```c
scanf("%f %f %f",&num1,&num2,&num3);
```

the runtime library starts reading characters one by one from the buffer.

```
stdin Buffer

↓

10

↓

num1

↓

20

↓

num2

↓

30

↓

num3
```

After successfully reading the required values,

only the newline character remains inside the buffer.

```
stdin Buffer

+---------+
| '\n' |
+---------+
```

This remaining newline becomes important during the next input operation.

---

# Why Pressing Enter Generates '\n'

Suppose the user types

```
A
```

Although only one visible character appears,

the keyboard actually generates

```
'A'
'\n'
```

The newline character (`'\n'`) is automatically generated when the Enter key is pressed.

Therefore,

the runtime stores

```
stdin Buffer

+--------------+
| 'A' | '\n' |
+--------------+
```

# Character Input using getchar()

The following example demonstrates how characters are retrieved from the input buffer.

```c
char c1,c2,c3,c4,c5,c6;

printf("Enter any 6 characters of your choice\n");
fflush(stdout);

c1 = getchar();
getchar();

c2 = getchar();
getchar();

c3 = getchar();
getchar();

c4 = getchar();
getchar();

c5 = getchar();
getchar();

c6 = getchar();

printf("\nASCII Codes : %u,%u,%u,%u,%u,%u",
       c1,c2,c3,c4,c5,c6);
```

# Execution Example

Suppose the user enters

```
A
```

The keyboard sends

```
'A'
'\n'
```

The buffer becomes

```
stdin Buffer

+---------------+
| 'A' | '\n' |
+---------------+
```

The statement

```c
c1 = getchar();
```

reads only the first character.

```
stdin Buffer

Before

+---------------+
| 'A' | '\n' |
+---------------+

        │

getchar()

        ▼

After

+---------+
| '\n' |
+---------+

c1 = 'A'
```

Notice that the newline character still exists inside the buffer.

---

# Why Another getchar() is Used

Immediately afterwards,

```c
getchar();
```

is executed.

This second call removes the newline character.

```
stdin Buffer

Before

+---------+
| '\n' |
+---------+

        │

getchar()

        ▼

Buffer Empty
```

Without removing the newline,

the next

```c
c2 = getchar();
```

would immediately read

```
'\n'
```

instead of waiting for another user-entered character.

Therefore,

the second `getchar()` clears the newline generated by pressing Enter.

---

# Why while(getchar() != '\n') is Used

Sometimes the user enters more characters than required.

Example

```
HELLO123
```

The input buffer becomes

```
+--------------------------------------+
| H | E | L | L | O | 1 | 2 | 3 | '\n' |
+--------------------------------------+
```

To completely empty the input buffer,

the following statement is used.

```c
while(getchar() != '\n')
{
    // Read and discard characters
}
```

# Holding the Console Window

In host-side applications,

the following code is commonly used.

```c
printf("\nPress Enter to Exit...");
getchar();
```

Purpose:

- Prevent the console window from closing immediately.
- Allow the user to read the program output.
- Wait until the Enter key is pressed before terminating the application.

This technique is primarily used for desktop console applications and is generally unnecessary in STM32 firmware because embedded applications usually execute continuously inside an infinite loop (`while(1)`).

# Relationship to STM32 UART Communication

Although this experiment uses keyboard input,

the same concept applies to UART communication on STM32.

```
Desktop Application

Keyboard

↓

stdin Buffer

↓

scanf()

↓

Variables
```

becomes

```
STM32 Firmware

UART RX Register

↓

UART RX Buffer

↓

UART Driver

↓

Application
```

Similarly,

```
printf()

↓

stdout Buffer

↓

Console
```

becomes

```
printf()

↓

UART Driver

↓

USART Peripheral

↓

TX Pin

↓

Serial Terminal
```

Understanding console buffering on a host computer provides a strong conceptual foundation for implementing UART drivers, circular buffers, and interrupt-driven communication on STM32 microcontrollers.
